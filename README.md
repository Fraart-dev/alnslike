
# ALNSlike

Header-only фреймворк на C++20 для проектирования и использования алгоритмов локального поиска и метаэвристик на основе Adaptive Large Neighborhood Search (ALNS). Предоставляет модульный каркас солвера, набор критериев принятия, селекторы с адаптивным выбором  операторов на основе многоруких бандитов, интерфейсы для реализации  предметных операторов.

## Возможности

- Header-only, C++20, без внешних зависимостей.
- Солвер собирается из независимых компонентов: шаг поиска, критерий принятия, селекторы операторов, операторы, генератор начального решения, постобработка. Любой компонент можно заменить собственной реализацией через интерфейс.
- Шаги поиска:
  - `AlnsStep` — последовательность ruin → repair с откатом при отклонении.
  - `LocalSearchStep` — локальный оператор с двухфазным применением (вычисление дельты и применение).
- Критерии принятия: `SimulatedAnnealingCriterion` (стандартный и с возможностью разогрева), `GreatDelugeCriterion`, `LateAcceptanceCriterion`, `StepCountingCriterion`, `DiversifiedLateAcceptanceCriterion`, `GreedyAcceptanceCriterion`, `EpsilonGreedyCriterion`.
- Селекторы операторов: `UniformRandomSelector`, `ClassicRouletteSelector`, `EpsilonGreedySelector`, `UcbSelector`, `DiscountedUcbSelector`, `ThompsonSamplingSelector`, `Exp3Selector`.
- Реализация решения и операторов для задачи коммивояжёра (TSP).
- Интерфейсы для реализации собственных `Solution`, операторов, критериев, селекторов, генераторов и постобработки.

Требования
Компилятор с поддержкой C++20
Для сборки тестов и примеров потребуется CMake 3.14+.

## Быстрый старт

### Подключение

**Через CMake:**

```cmake
add_subdirectory(alnslike)
target_link_libraries(my_target PRIVATE alnslike::alnslike)
```

Или напрямую через компилятор:
```g++ -std=c++20 -I/path/to/alnslike/include main.cpp -o main``` 

Минимальный пример

Полный код примера находится в [`examples/minimal/main.cpp`](examples/minimal/main.cpp).

Пример демонстрирует поиск минимума функции `x²` для целочисленного решения. Используются:

- реализация `IntSolution` — решение, хранящее целое число `x`, целевая функция `x²`;
- реализация двух операторов `ShiftOperator`, изменяющих значение на `+1` или `-1`;
- подключение готового селектора `ClassicRouletteSelector` на основе адаптивной рулетки;
- подключение готового критерия принятия `SimulatedAnnealingCriterion`;
- сборка и запуск солвера через `SolverBuilder`.

## Архитектура

ООП-вариант библиотеки построен на абстрактных интерфейсах с виртуальными методами. Пользователь реализует свои классы, наследующие эти интерфейсы, и передаёт их в `SolverBuilder`.

- `Solution` — состояние текущего решения. Обязательные методы: `GetCost()`, `GetFeasibilityViolation()`, `Clone()` (глубокое копирование), `CopyFrom()` (копирование без выделения памяти). Опциональный `IsSolved()` позволяет остановить поиск досрочно.
- `LocalOperator` — оператор локального изменения решения: `Propose()` вычисляет дельту (может изменять решение, если дельту невозможно вычислить иначе), `Finalize()` применяет или откатывает изменение в зависимости от флага `is_accepted`.
- `RuinOperator` / `RepairOperator` — операторы разрушения и последующего восстановления. Метод `Undo()` откатывает изменения. Сохраняют общие данные в `MoveCache`.
- `MoveCache` — кеш для обмена данными между операторами внутри одного шага. Очищается перед каждым шагом.
- `OperatorSelector` — осуществляет выбор оператора. `Select()` возвращает индекс, `UpdateWeights()` корректирует вес на основе `OperatorReward`, `ResetPeriod()` сбрасывает статистику.
- `AcceptanceCriterion` — критерий принятия. `Accept()` возвращает `true`, если решение принимается, и `false` при отклонении. `Update()` вызывается после `Accept()` и обновляет внутреннее состояние.
- `SolutionGenerator` — генерирует начальное решение, если оно не задано явно.
- `PostProcessor` — постобработка лучшего решения после остановки цикла.

- `SearchStep` — интерфейс осуществления одного шага поиска. Реализация выбирает оператор(ы), применяет их к текущему решению, взаимодействует с критерием принятия и возвращает `StepResult`. Конструируется с набором операторов и селектором(ами).

Готовые реализации `SearchStep`:

- `AlnsStep` — последовательность ruin -> repair. При отклонении критерием вызывает `Undo()` обоих операторов.
- `LocalSearchStep` — использует локальные операторы: `Propose()` -> критерий -> `Finalize()`.

Солвер конструируется через `SolverBuilder`. Обязательные компоненты:

- `SearchStep` (содержит операторы и селектор);
- `AcceptanceCriterion`;
- начальное решение `SetInitialSolution` или его генератор `SetGenerator`.

Остальное опционально.

Условия остановки: `max_iterations`, `max_iterations_without_improvement`, `timeout`. Проверка времени выполняется с частотой, задаваемой `time_check_mask` (по умолчанию каждые 1024 итерации через битовую маску).

`Solver` — move-only, копирование запрещено.

## Встроенные критерии принятия

Все классы находятся в `alnslike::builtin::criteria` и реализуют `core::AcceptanceCriterion`. Каждый критерий имеет конфигурационную структуру `Configuration` с параметрами и значениями по умолчанию.

### SimulatedAnnealingCriterion

Классический критерий иммитации отжига. Улучшения принимаются всегда, ухудшения — с вероятностью `exp((current_cost - new_cost) / T)`.

Параметры:

- `initial_temperature` — начальная температура (по умолчанию 1000).
- Вариант 1: `cooling_rate` — коэффициент охлаждения (умножается на каждом шаге).
- Вариант 2: `max_iterations` и `final_temperature` — коэффициент рассчитывается автоматически, чтобы за `max_iterations` достичь `final_temperature`.

### HeatingSimulatedAnnealingCriterion

Отжиг с циклическим нагревом. Когда температура опускается до `minimum_temperature`, выполняется нагрев до `current_peak_temperature * cycle_decay_factor`.

Параметры:

- `initial_temperature` — начальная температура.
- `minimum_temperature` — температура, при достижении которой начинается новый цикл нагрева.
- `cycle_decay_factor` — множитель для пиковой температуры при нагреве (в (0, 1]).
- Задаётся либо `iterations_per_cycle` , либо просто `cooling_rate`.

### GreatDelugeCriterion

Принимает решение, если оно не хуже текущего или не превышает текущий уровень воды. Уровень снижается на `rain_speed` после каждой итерации.

Параметры:

- `initial_water_level` — начальный уровень воды (по умолчанию 1000).
- `rain_speed` — скорость снижения уровня (по умолчанию 1)).

### LateAcceptanceCriterion

Стандартный Late Acceptance Hill Climbing. Принимает решение, если оно лучше текущего или лучше стоимости решения `history_length` итераций назад. Отклоняет любые переходы, увеличивающие нарушение ограничений (`feasibility_delta > 0`).

Параметры:

- `history_length` — длина истории стоимостей (по умолчанию 1000).

### DiversifiedLateAcceptanceCriterion

Вариант позднего принятия с механизмом диверсификации. История обновляется только при диверсификации (текущая стоимость хуже старой) или интенсификации (текущая стоимость лучше старой и переход принят). Принимает, если решение лучше текущего или строго меньше максимальной стоимости в истории.

Параметры:

- `history_length` — длина истории (по умолчанию 1000).

### StepCountingCriterion

Каждые `step_period` итераций порог фиксируется на текущей стоимости. Принимает решение, если оно лучше текущего или строго меньше порога.

Параметры:

- `step_period` — период счётчика шагов (по умолчанию 50).

### GreedyAcceptanceCriterion

Жадный критерий. Принимает только неухудшающие решения (`new_cost <= current_cost`).

### EpsilonGreedyAcceptanceCriterion

Эпсилон-жадный критерий. Улучшения принимаются всегда; ухудшения — с вероятностью `epsilon`.

Параметры:

- `epsilon` — по умолчанию 0.1.

## Встроенные селекторы операторов

Все классы находятся в `alnslike::builtin::selectors` и реализуют `core::OperatorSelector`. Конструкторы принимают количество операторов.

### RewardWeights

Общая структура для настройки числовых наград, используемых большинством селекторов. Поля: `rejected` (по умолчанию 0), `accepted` (1), `improved_objective` (2), `improved_feasibility` (3), `new_best` (6). Метод `Determine(reward)` возвращает награду на основе `OperatorReward`.

### UniformRandomSelector

Равномерный случайный выбор.

### ClassicRouletteSelector

Рулетка с весами, обновляемыми по экспоненциальному скользящему среднему.

Параметры:

- `reaction_factor_rho` — скорость реакции веса на новую награду (по умолчанию 0.01).
- `min_weight` — минимальный вес (по умолчанию 0.01).
- `weights` — настройки `RewardWeights`.

### EpsilonGreedySelector

Эпсилон-жадный выбор: с вероятностью `epsilon` — случайный оператор, иначе — с наибольшей средней наградой.

Параметры:

- `epsilon` — вероятность случайного выбора (по умолчанию 0.1).
- `weights` — настройки `RewardWeights`.

### UcbSelector

Классический UCB1 для стационарных сред.

Параметры:

- `exploration_constant` — коэффициент исследования (по умолчанию sqrt(2)).
- `weights` — настройки `RewardWeights`.

### DiscountedUcbSelector

Дисконтированный UCB для нестационарных сред, статистика затухает с коэффициентом `gamma`.

Параметры:

- `exploration_constant` — коэффициент исследования (по умолчанию sqrt(2)).
- `gamma` — коэффициент дисконтирования (по умолчанию 0.9985).
- `weights` — настройки `RewardWeights`.

### Exp3Selector

Алгоритм Exp3 для нестационарных сред с полной информацией.

Параметры:

- `gamma` — коэффициент исследования (по умолчанию 0.1).
- `weights` — настройки `RewardWeights`.

### ThompsonSamplingSelector

Семплирование Томпсона. Для каждого оператора выбирается θ из `Beta(α, β)`, где α — число принятых переходов, β — число отклонённых. Выбирается оператор с максимальным θ. Начальные α = β = 1.
